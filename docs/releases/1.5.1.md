# Orka 1.5.1 — preserved PR recovery fences

Preserved PR auto-recovery now verifies that the single clean, quiescent
worktree is checked out at the authenticated GitHub PR head and tree. It
refreshes the remote PR immediately before checkpoint mutation and requires any
recorded execution unit to be proven absent.

A cross-ledger recovery fence atomically blocks stale workers from opening a
new usage reservation while the controller rebinds the ticket. Attempt
capabilities are revalidated before every provider request and while its usage
reservation is created. The authenticated PR/worktree binding is also
revalidated at reservation and launch, then consumed once the controller-owned
execution unit is established.

The local worker supervisor also treats a process-group permission error as an
already-finished child when process status confirms termination, closing a
macOS teardown race without weakening live-worker cleanup.
