# Orka 1.8.39

Orka 1.8.39 adds the first stable, read-only observability surface for the
authoritative transactional runtime.

## What changed

- Adds versioned redacted event, cursor, and metrics contracts for dashboards,
  log drains, and future OpenTelemetry adapters.
- Adds `sprint-supervisor.py events` with deterministic repository-bound cursor
  replay and JSON or JSONL output.
- Adds `sprint-supervisor.py metrics` with stable work, lane, transition, retry,
  recovery, provider-hold, cost, and completion groups.
- Strictly allowlists output fields. Raw event payloads, aggregate identities,
  tickets, paths, prompts, credentials, source text, and provider bodies never
  cross the observer boundary.
- Copies each view under a short read-only SQLite transaction and closes the
  database before writing output, so slow observers do not retain runtime
  locks.
- Reports desktop subscription usage as `unmetered` with no synthetic zero-cost
  value.

## Compatibility

The change is additive and requires an active transactional runtime cutover.
It does not alter scheduling, worker routing, provider use, budgets, gates,
repository configuration, or event-store migrations. Existing status and
control commands are unchanged.
