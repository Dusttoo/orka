# Orka 1.5.5

Orka 1.5.5 restores safe recovery and repaired-head review progression without
relaxing execution, attempt, or review gates.

## Recovery fixes

- `attach` now consumes only its one-use bearer token and retains the
  attempt-scoped launch evidence needed to verify cooperative terminal cleanup,
  automatic recovery, and the implementation baseline.
- A recovered PR with no current attempt token remains pending until
  controller reservation mints a fresh token. Restart no longer creates an
  unactionable `needs_repair` state with no authenticated attempt.

## Review-ledger compatibility

- Legacy sequential review rounds are deterministically assigned to logical
  repair generations using their durable timestamps and repair artifacts. Each
  migrated result must still match one consumed gate permit and one exact head;
  a historically demoted FAIL remains blocked for explicit reconciliation.
- A pending, unreviewed repair produced by the affected runtime has its required
  gates restored from the preceding generation and prior durable gate set.
- New repairs retain the complete prior gate topology. Ambiguous chronology or
  partially consumed repair evidence fails closed rather than rewriting review
  history.
- Implementation progress must be the authenticated worker checkout's current
  HEAD, preventing an unrelated repository descendant from receiving progress
  or continuation credit.

All historical findings, raw verdicts, repair counts, branches, PR bindings,
and attempt counters remain intact.
