# Orka 1.6.3

Orka 1.6.3 gives native gateway reservations an evidence-bound reconciliation
path, so a sprint ticket whose worker hit a provider read timeout can be
restarted after the operator confirms the request never reached the provider.

## Gateway reservation reconciliation

- `reconcile-reservations` now accepts `not-found` entries for reservations
  written by the controller-owned Claude or Codex gateway, which never have a
  `.llm-runs` marker.
- Acceptance requires the ticket's controller launch record for that exact
  invocation, a terminal execution record written after the reservation, and
  the controller's liveness check proving the execution unit is gone.
  Cooperative units also need a closed gateway and no surviving worker group.
- Live or unknown units, mismatched runs or tickets, completed outcomes, empty
  evidence, manifests outside the repository, duplicates, non-gateway
  reservations without a run marker, and gateway reservations that also have a
  run marker remain refused.
- Each release writes a durable audit record under
  `.orchestration/.llm-usage/gateway-reconciliations/` before touching the
  ledger. Re-applying the same manifest is idempotent.
- `reservation-migration-plan` labels each entry's `source` and lists
  reservations neither path can accept under `excluded` with the reason.
- New reservations record `origin` (`api-run`, `native-gateway`,
  `codex-gateway`, or `provider-batch`). Existing ledgers need no migration;
  unmarked gateway-shaped reservations are recognized conservatively.
- `restart-ticket` no longer reports outstanding reservations for a ticket once
  its gateway reservations are reconciled.
