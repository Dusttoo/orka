# Orka 1.8.7

Orka 1.8.7 completes the first durable-supervisor delivery sequence with
authenticated crash takeover and restart/idempotency integration coverage.

## Added

- Unclean supervisor restarts acquire a new lease generation only after exact
  predecessor absence, unchanged lease identity, and durable-state validation.
- Planning, dispatch, operator requests, timers, ticket bindings, and pause or
  drain mode survive takeover.
- A separate state-digest receipt detects incomplete or externally modified
  durable snapshots before recovery.
- Exact terminal-result replays are idempotent in the sprint controller, while
  changed results with the same attempt remain rejected.
- A reproducible operator failure-injection and recovery runbook.

## Compatibility and safety

Clean starts remain compatible with earlier Orka state. Automatic takeover of
an unclean predecessor requires state written by this release, so older
ambiguous crash state remains fail-closed. Runtime, contract, config, lease, or
process-identity drift never authorizes a takeover. Existing review, security,
budget, merge, and external-side-effect gates are unchanged.
