# Orka 1.5.6

Orka 1.5.6 adds a narrow, authenticated recovery path for preserved repair
work that older runtimes left without a current attempt token.

## Tokenless repair recovery

- `recover-terminal` can now recover `needs_repair` only when the ticket still
  has its PR and branch and every execution-unit identity field is empty.
- Recovery still requires a one-use, root-issued, attempt-bound capability.
- The operation preserves the PR, branch, history, attempt counters, review
  ledger, and spend accounting while returning the ticket to `pending` so the
  next normal reservation can mint a fresh attempt token.
- Tickets with a current token, missing PR binding, or live or ambiguous
  execution evidence continue to fail closed.

This resolves the unrecoverable state seen when an earlier repair restart
preserved the PR but lost the attempt identity. It does not loosen normal
relaunch, budget, review, or merge authority.
