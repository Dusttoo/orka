# Orka 1.8.32

Orka 1.8.32 establishes the accepted replaceable execution-backend boundary
for the Orka 2 worker runtime.

## What changed

- Added the versioned `orka.execution-backend/v1` machine contract for backend
  discovery, capability negotiation, launch, attach, heartbeat, progress,
  cancellation, inspection, and terminal evidence.
- Bound every lifecycle operation to the exact repository, job, phase,
  attempt, dispatch, execution unit, worktree, and supervisor fence.
- Separated containment claims from provider capabilities so a backend cannot
  derive filesystem, network, credential, or process isolation from a model
  route.
- Defined fail-closed liveness semantics for inspection timeout, permission
  failure, process identity reuse, and mechanically proven absence.
- Delegated job and terminal evidence validation to the canonical phase-worker
  contract, including exact identities and mandatory capabilities. Nested
  forbidden session-state keys are rejected before backend dispatch without
  treating ordinary string mentions as session state.
- Added mechanically bound launch and cancellation receipts, supervisor-owned
  fence semantics, and permanent single-use execution tombstones. Production
  route integration must persist those tombstones before it can use the new
  boundary across restarts.
- Added a deterministic, credential-free fake backend and shared fixtures that
  exercise fresh phase context, stale-execution fencing, cancellation
  acknowledgement, unknown inspection, and capability refusal. The fake
  backend is explicitly test-only and rejected outside conformance mode.
- Documented how the current Codex desktop, Claude desktop, and direct API
  paths map to the common boundary without granting a backend scheduling,
  budget, policy, replacement, or merge authority.

## Compatibility

This release adds an accepted contract and conformance kit without changing
the authoritative Orka 1.x worker launcher. Existing repository configuration
and Codex, Claude, and API routes continue to work unchanged. Production route
integration behind the new interface remains part of issue #131 and will be
delivered separately.
