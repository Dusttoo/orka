# Orka 1.6.1

Orka 1.6.1 fixes two false visual-QA failures and adds a safe review-ledger
transition for PR heads that move after a completed review generation.

## Settled Next.js RSC navigation

- An aborted same-origin RSC GET is ignored when another RSC request for the
  same pathname completed with a 2xx response in the same capture step, whether
  that completion occurred before or after the abort.
- The exception still requires the expected page state and no page errors.
  Aborted document navigations, unstarted requests, cross-origin failures, and
  RSC failures without a successful same-path completion remain blocking.
- Regression coverage reproduces the recorded PNP-149 and PNP-21 desktop
  request sequences.
- The reported mobile metadata-prefetch failure is closed as non-reproducing:
  recorded `next-router-prefetch` aborts are already ignored by the current
  classifier, and a dedicated regression now protects that behavior.

## Review generation rebinding

- `review-ledger.py rebind-generation` starts a fresh review generation when a
  non-findings commit moves a PR head after its prior review generation has
  completed.
- The command requires the exact repository HEAD, an auditable reason,
  authoritative prior gate evidence, no open blockers, and no outstanding
  review permits.
- It preserves review history, findings, strikes, escalation evidence, and
  repair-cycle accounting. It cannot substitute for `record-repair` when open
  findings exist.
- Claude commands and Codex skills now document the same transition.

## Minimum-version enforcement

- Repository `minimum_orka_version` policy now applies before PR review permits
  are issued and before merge evidence is recorded or asserted, not only during
  sprint-captain preflight.
- The gate workflows run the same shared policy check explicitly. Review and
  merge scripts repeat it mechanically and fail closed for missing, malformed,
  or incompatible runtime evidence.
