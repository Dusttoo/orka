# Orka 1.8.3

Orka 1.8.3 adds the first host-owned Orka 2 runtime slice: a detached
repository supervisor process with an exclusive lease and deterministic
lifecycle control.

## Supervisor lifecycle process

- `scripts/sprint-supervisor.py start` launches outside the invoking terminal,
  Claude, Codex, or SSH session and acquires one exclusive repository lease.
- `status`, `pause`, `resume`, `drain`, and `stop` use a private local control
  socket and idempotent request IDs.
- State records exact process identity, lease UUID and generation, contract and
  config fingerprints, transitions, and a single clean lease release.
- Duplicate starts fail without unlinking or otherwise disturbing the active
  supervisor's control channel.
- A replaced lease inode stops the supervisor fail-closed.
- Unclean predecessor death remains refused until the later heartbeat and
  split-brain slice supplies authenticated takeover evidence.

## Contract clarification

The version-1 supervisor contract now includes the missing global
`operator_stopped` event. This keeps an explicit stop distinct from lease loss,
invalid state, or false sprint completion evidence.

## Compatibility

Existing Orka 1.x repositories require no configuration migration. Add
`.orchestration/.supervisor/` to the consuming repository's `.gitignore` before
using the new process. This release does not yet synchronize or plan tickets,
dispatch workers, or recover a crashed supervisor.
