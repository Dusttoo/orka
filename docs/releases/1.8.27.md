# Orka 1.8.27

Orka 1.8.27 completes the first transactional controller-routing slice tracked
by issue #125.

## Changed

- Direct sprint-controller commands transparently route through the active,
  authenticated repository-supervisor socket after transactional cutover.
- Supervisor planning and direct controller commands use private ephemeral JSON
  materializations and commit through generation-fenced runtime documents.
- Requests bind repository identity, cutover activation, supervisor fence,
  command identity, and the expected controller-generation set.
- Exact duplicate command delivery is idempotent; changed payloads, stale
  generations, path overrides, malformed outputs, and multi-document mutations
  fail closed.

## Compatibility

- Repositories that have not activated transactional cutover retain the
  existing file-backed controller behavior.
- No repository configuration change is required.
- Cutover repositories require a live Orka 1.8.27-or-newer supervisor before
  invoking sprint-controller commands directly.
