# Orka 1.8.31

Orka 1.8.31 qualifies the Orka 2 transactional runtime cutover end to end.

## What changed

- Added a production cutover qualification suite covering the shadow import,
  activation, pause, resume, status, unclean restart, clean stop, and
  rollback boundary.
- Proved that a running legacy supervisor blocks activation and that an
  incompatible runtime refuses the cutover before changing either SQLite or
  legacy JSON state.
- Proved that controller and supervisor JSON checkpoints remain byte-for-byte
  read-only after activation, including across operator controls and restart.
- Added an acceptance trace from the parent transactional-cutover issue to the
  exact implementation and regression suites that enforce each invariant.

## Compatibility

Repositories remain on the file-backed Orka 1.x runtime until an operator
explicitly imports and activates the transactional cutover. An activated
repository requires Orka 1.8.31 or newer. Rollback remains available only
before the first authoritative transactional write.
