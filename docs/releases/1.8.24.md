# Orka 1.8.24

Orka 1.8.24 implements the transactional cutover-authority foundation tracked
by issue #124, the first ordered implementation slice of #118.

## Added

- A version-3 event-store migration for repository cutover receipts and
  generation-fenced runtime documents.
- Explicit, content-addressed cutover activation under the stopped-supervisor,
  migration, and repository-initialization locks.
- A private repository marker containing the minimum compatible Orka version,
  exact repository identity, and normalized legacy shadow digest.
- Seeded generation-zero controller and supervisor documents without making a
  production runtime write.
- Exact-replay activation and rollback across marker/database crash boundaries.
- Permanent rollback closure after the first authoritative runtime-document
  event.
- Fail-closed refusal in the legacy controller and supervisor writers whenever
  the cutover marker is active.

## Compatibility

- Existing repositories do not activate cutover automatically.
- Before explicit activation, the JSON controller and supervisor behave exactly
  as in Orka 1.8.23.
- Activating with 1.8.24 creates an intentional maintenance hold. Transactional
  production routing arrives in the ordered #125 through #127 slices.
- Legacy inputs remain present and unchanged.
