# Orka 1.8.19

Orka 1.8.19 accepts the transactional event-store architecture in issue #76
and decomposes its production delivery into independently reviewable slices.

## Changed

- Selects a repository-scoped SQLite event store with an append-only journal,
  transactionally maintained projections, and one supervisor-owned writer.
- Defines a Git-common-directory runtime root and repository UUID so linked
  worktrees share one domain while sibling bare repositories remain isolated.
- Selects a canonical Git blob as policy authority instead of trusting the
  invoking feature worktree or silently using compiled defaults.
- Defines atomic reservation, launch, external-operation, and completion
  boundaries plus deterministic JSON export and offline legacy import.
- Version-gates WAL mode for SQLite's documented WAL-reset fix and specifies a
  full-synchronous rollback-journal fallback for older supported runtimes.
- Defines backup, integrity, replay, corruption, cutover, and cross-platform
  requirements without replacing the current production checkpoint format.

## Verification

- Executable schema prototype covering every planned state-store entity.
- Twelve simultaneous worker completions with no lost events or projections.
- Stale optimistic completion rollback without an orphan journal event.
- Immutable event history, SQLite integrity check, foreign-key check, and
  byte-stable canonical export.
- Full repository regression suite.
