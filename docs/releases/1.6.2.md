# Orka 1.6.2

Orka 1.6.2 fixes three review-ledger continuation deadlocks without weakening
repair limits or provider reconciliation rules.

## Final authorized repair reviews

- A repaired head that is already awaiting review remains reviewable even when
  the last authorized repair consumed the final fix cycle.
- Durable escalation resumes only after that required review fails. A passing
  review can still clear the gate.
- Existing ledgers require no reset or migration.

## Rebound-head reviews after an exhausted repair budget

- A generation created by `rebind-generation` can run its required gates even
  when historical repairs exhausted the fix-cycle budget.
- Rebinding does not replenish repair cycles or authorize another repair.
- If the rebound review finds blockers, the exhausted ledger returns to human
  escalation after every required gate has completed.

## Recoverable invalid desktop review output

- `permit-review` now idempotently returns the same phase permit when it is
  still unstarted for the exact role, head, subject, and generation.
- A locally invalid structured result can therefore be corrected and retried
  without fabricating another reviewer or editing ledger state.
- Started provider reviews still require reconciliation, and completed review
  receipts still require ledger recording.
- Reviewer schema guidance, round briefs, and reviewer roles now explicitly
  forbid whitespace and prose in `<path>:<symbol>` component keys.
