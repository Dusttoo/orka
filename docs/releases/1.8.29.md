# Orka 1.8.29

Orka 1.8.29 makes supervisor state authoritative in the transactional event
store after explicit runtime cutover, completing issue #126.

## Changed

- Holds one supervisor-owned database writer for the full lease lifetime.
- Commits supervisor planning, dispatch, attempts, claims, retry timers,
  decisions, and external-operation ambiguity as one consistent generation.
- Shares the supervisor writer with controller commands instead of opening a
  second production write connection.
- Reads status and restart state from the transactional generation after
  cutover and stops writing the legacy supervisor JSON checkpoint.
- Rejects worker and adapter writer acquisition while the supervisor owns the
  store.
- Serializes concurrent completion snapshots without lost state and rejects
  stale closed-writer reuse.

## Compatibility

- Pre-cutover repositories continue using the existing file-backed supervisor
  and controller checkpoints without behavioral changes.
- Existing cutover imports that seeded `supervisor:primary` resume from that
  exact generation; cutovers without a prior supervisor document create it on
  first supervisor persistence.
- No repository configuration change is required.
