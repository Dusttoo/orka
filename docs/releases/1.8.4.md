# Orka 1.8.4

Orka 1.8.4 adds the deterministic synchronization and planning loop to the
host-owned sprint supervisor introduced in 1.8.3.

## Added

- The detached supervisor synchronizes Jira and controller state through the
  existing authenticated adapter, then publishes an evidence-bound plan and
  summary without a model turn.
- Provider cooldowns and ticket retry times become durable wake deadlines.
- Identical synchronized evidence produces an identical plan digest; plan
  history records only meaningful changes.
- Authenticated sprint completion, hard sprint budget exhaustion, unavailable
  routes, operator commands, lease loss, and invalid durable state follow the
  versioned lifecycle contract.
- Ticket-local blockers and decisions remain isolated while independent work
  stays visible in the plan.
- Repositories can optionally tune `supervisor_sync_interval_seconds` from 5 to
  3600 seconds. Existing Orka 1.x configurations remain compatible.

## Boundary

This release reports controller-authorized launch, repair, recovery,
decomposition, and reconciliation work. It does not reserve tickets or launch
workers; that is the next independently reviewable runtime slice.
