# Orka 1.5.0 — autonomous sprint convergence

Orka can now keep more recoverable sprint work moving without weakening review,
budget, or execution fences.

- Existing PRs drain before fresh tickets. Repositories may opt into automatic
  recovery when authenticated GitHub identity, exact commit/tree evidence, one
  clean worktree, and host quiescence all agree.
- Approved repository decisions are reusable by stable key, so related tickets
  are re-scoped under reviewed product policy instead of repeatedly stopping on
  the same question.
- Decomposition can require repository-selected contracts on every generated
  slice. Slice dependency links are verified both immediately in Jira and again
  through fresh controller-owned inventory before children become actionable.
- Historical ambiguous provider reservations can be reconciled from a bounded,
  repository-bound evidence manifest. The bulk path only accepts provider-proven
  `not-found` results; completed usage still requires exact individual settlement.

All behavior is generic and config-driven. Automatic preserved-PR recovery is
disabled by default, while finish-first PR ordering is enabled by default.
