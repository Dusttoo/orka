# Orka 1.8.37

Orka 1.8.37 defines a provider-neutral boundary for narrowly scoped operator
authority while retaining the current root-owned helper as the reference
provider.

## What changed

- Adds a versioned authority-provider contract for budget extensions, relaunch
  ceilings, exact terminal recovery, PR repair cycles, and bounded restarts.
- Defines host-owned provider discovery, strict class-specific scopes, opaque
  one-use capabilities, expiry, revocation, replay denial, and audit receipts.
- Adds a host-pinned compatibility adapter for the installed local root helper;
  repository and worker input cannot select its executable or environment.
- Makes pending grants revocable, adds exact terminal-recovery revocation, and
  fsyncs authority directory entries after replacements and removals.
- Adds credential-free conformance fixtures and lifecycle tests covering
  issuance, verification, consumption, pending revocation, replay, and outage.

## Trust boundary

Authority providers grant only the single bounded action associated with an
authority class. They cannot approve reviews, bypass security gates, authorize
merges, or permit destructive actions. Provider outages and malformed data
fail closed without manufacturing authority.

This release defines the provider boundary and local compatibility profile. It
does not route scheduler state through a new provider or add cloud IAM, OAuth,
or a hosted approval service. Transactional coupling to scheduler state remains
part of the separate durable authority-state work.

## Host upgrade

Hosts using operator authority should reinstall the bundled helper so pending
revocation and directory durability changes are active:

```bash
sudo scripts/install-operator-authority.sh <runtime-user>
```
