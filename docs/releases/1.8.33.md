# Orka 1.8.33

Orka 1.8.33 adds the first operational-proof slice of the transactional event
store: deterministic, fail-closed startup diagnostics before supervisor
planning or admission.

## What changed

- Added the versioned `orka.startup-diagnostic` machine contract with a fixed
  check order, stable reason codes, and sanitized operator next actions.
- Added read-only startup verification for SQLite `quick_check(1)`, foreign
  keys, the exact schema and migration ledger, repository identity, canonical
  policy, cutover activation, minimum Orka version, and owner-only runtime
  permissions.
- Bound successful supervisor startup and status to the exact receipt that
  admitted that supervisor generation.
- Added `sprint-supervisor.py diagnose` so operators can obtain the same receipt
  without starting planning or workers.
- Kept full `integrity_check` as an explicit deeper diagnostic and preserved
  compatible 1.x/pre-cutover startup behavior.
- Added deterministic snapshots and falsifying tests for each invariant,
  including proof that a failed receipt creates no job, attempt, reservation,
  or launch.

## Compatibility

The diagnostic is read-only and does not repair or rewrite the database,
sidecars, identity marker, policy, or cutover marker. Legacy repositories keep
their existing preflight and state behavior. Backup, restore, replay,
takeover, and destructive repair remain outside this release and continue in
the later #119 slices.
