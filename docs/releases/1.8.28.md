# Orka 1.8.28

Orka 1.8.28 implements supervisor-managed disposable phase execution tracked
by issue #114.

## Added

- Adds a host-owned phase execution state machine implementing the versioned
  `orka.phase-worker-protocol` contract.
- Negotiates adapter capabilities before dispatch and gives every invocation a
  fresh model context, dispatch identity, and execution-unit identity.
- Binds launch attachment, progress, heartbeat, cancellation, and terminal
  evidence to the exact attempt and supervisor fence.
- Preserves a stable logical job and external-operation idempotency key when a
  failed execution unit is replaced.
- Classifies malformed output into bounded ticket-local recovery.
- Requires cancellation acknowledgement or an explicit fence before admitting
  a replacement.
- Reconciles exact live and absent execution evidence on restart without
  duplicating a worker, including successor attribution of an older dispatch
  fence.

## Compatibility

- Existing Orka 1.x ticket-workflow launches remain valid and are represented
  as the compatibility `ticket-workflow` phase.
- Jobs created by earlier supervisors without phase-execution state retain
  their existing terminal-result path.
- No repository configuration or state migration is required.
