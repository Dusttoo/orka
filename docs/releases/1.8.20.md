# Orka 1.8.20

Orka 1.8.20 implements the repository identity and canonical policy boundary
accepted in ADR 0001 and tracked by issue #51.

## Added

- Private, atomic, idempotent repository identity initialization beneath the
  absolute Git common directory.
- Distinct runtime roots for sibling bare repositories and one shared identity
  across ordinary and bare-backed linked worktrees.
- Operator-selected canonical policy bindings to fully qualified Git refs and
  repository-relative blobs.
- Exact policy commit, blob, and SHA-256 provenance in repository status and
  captain preflight.
- Read-only discovery of legacy worktree and historical parent-level state.

## Compatibility

- Existing JSON controller state remains authoritative and is not moved or
  deleted. Explicit legacy import and production cutover remain separate
  tracked slices.
- Repositories without the new marker continue in `legacy-uninitialized` mode.
- An initialized repository fails closed on identity mismatch, malformed or
  unsafe markers, or missing canonical policy.

## Verification

- Normal repository and ordinary linked-worktree identity sharing.
- Bare-backed worktrees and sibling bare-repository isolation.
- Atomic/private/idempotent initialization, copied identity rejection, policy
  drift protection, missing policy rejection, and ambiguous-state inventory.
- Existing initialization and API-agent regression suites.
