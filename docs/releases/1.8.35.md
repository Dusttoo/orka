# Orka 1.8.35

Orka 1.8.35 hardens the execution-backend authority introduced in 1.8.34.

## What changed

- Replays the exact durable terminal result after a controller-apply failure
  without requiring the transient result file or rerunning mutable external
  verification. A still-present file is only a tamper check.
- Separates terminal outcome authority from mechanical absence. A terminal
  receipt, cancellation acknowledgement, or logical supervisor fence never
  permits replacement while the exact process, process group/cgroup, gateway
  request, or provider job may still be live.
- Makes cancellation optional for routes that cannot mechanically cancel and
  observe absence. Those routes remain recoverable and replacement-unsafe.
- Binds adjacent-release backendless-job provenance to the exact event-store
  activation, committed source generation, payload digest, immutable event
  identity, and single CAS-committed target generation under the continuous
  sole-writer lock.
- Cross-checks each imported job against that authenticated top-level receipt;
  fabricated, missing, or tampered migration provenance fails closed.
- Authenticates launch metadata on restore, preserves tombstone death checks,
  and includes the schema-v4 execution-backend migration in the runtime
  fingerprint.

## Trust boundary

Authenticated migration evidence means integrity-bound within Orka's exclusive
event-store writer and private-local-filesystem boundary. This release does not
claim resistance to an actor who can rewrite SQLite and recompute unkeyed
digests; keyed or separately isolated authority remains future work.

## Compatibility

Existing Codex desktop, Claude desktop, and direct API routes remain supported.
Because their current adapters cannot prove mechanical cancellation and absence,
they do not advertise cancellation capability. Pre-cutover repositories retain
their established checkpoint behavior; backendless in-flight adjacent-release
compatibility is accepted only from authenticated transactional migration
history.
