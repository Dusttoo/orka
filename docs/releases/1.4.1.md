# Orka 1.4.1 — bounded Jira readiness paths

Jira decomposition can now advance newly created children through an explicit,
repository-approved sequence of status destinations when the project workflow
does not offer a direct transition to `Ready`. Each path is limited to five
unique statuses, must end in a configured launchable status, and may not pass
through blocked, completed, or prematurely launchable states.

The adapter verifies every transition's required-field metadata, observes the
exact resulting status before continuing, reconciles uncertain POST outcomes,
and resumes safely when an earlier run already reached a configured intermediate
status. Repositories without `jira_ready_transition_path` retain the existing
single-transition behavior.
