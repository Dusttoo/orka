# Orka 1.5.3

## Concurrent review generations

- Code and security results for the same exact PR head now share one logical
  review generation regardless of completion order.
- Every initial gate retains full blocking authority; a security PASS recorded
  first can no longer scope-freeze a later code-review FAIL.
- A partially recorded concurrent generation cannot report `gates-clear` while
  another issued gate remains outstanding.
- Reviewer responses do not consume repair-cycle allowance. Only explicit
  repair artifacts continue to advance that cap.

## Legacy ledger recovery

- `review-ledger.py migrate-concurrent-review` repairs the narrow legacy state
  where concurrent initial reviews were incorrectly numbered as separate
  rounds.
- Migration requires consumed generation-one permits for one exact shared head
  and can only restore ordering-demoted advisories as blockers. It cannot clear
  findings, reset repairs, or grant merge authority.

## Sprint recovery and state reconciliation

- Terminal recovery preserves existing branch and pull-request bindings, so a
  root-authorized restart returns preserved PRs to repair instead of treating
  them as fresh implementations.
- Restart authority no longer reclassifies orchestration-owned Jira workflow
  states such as `In Progress` as unrelated readiness decisions. A subsequent
  authoritative Jira sync also clears the narrow stale-status classification.
- Enabling automatic decomposition releases only tickets carrying the exact
  former policy-disabled hold and a preserved `decompose` assessment.
- Supervisor failures now stop and reap the worker before writing the terminal
  receipt. The receipt retains the real exit code, error, and cleanup evidence,
  allowing safe cooperative recovery without an unnecessary sudo intervention.

## Visual QA

- Same-origin Next.js RSC/router prefetches canceled by the browser are ignored
  as expected network noise. Aborted navigations, ordinary requests, and real
  network failures remain blocking visual-QA evidence.
