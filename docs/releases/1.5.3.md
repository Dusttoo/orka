# Orka 1.5.3

## Concurrent review generations

- Code and security results for the same exact PR head now share one logical
  review generation regardless of completion order.
- Every initial gate retains full blocking authority; a security PASS recorded
  first can no longer scope-freeze a later code-review FAIL.
- A partially recorded concurrent generation cannot report `gates-clear` while
  another issued gate remains outstanding.
- Reviewer responses do not consume repair-cycle allowance. Only explicit
  repair artifacts continue to advance that cap.

## Legacy ledger recovery

- `review-ledger.py migrate-concurrent-review` repairs the narrow legacy state
  where concurrent initial reviews were incorrectly numbered as separate
  rounds.
- Migration requires consumed generation-one permits for one exact shared head
  and can only restore ordering-demoted advisories as blockers. It cannot clear
  findings, reset repairs, or grant merge authority.
