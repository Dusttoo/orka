# Orka 1.8.5

Orka 1.8.5 connects the durable sprint supervisor to controller-owned worker
execution and terminal-result handling.

## Added

- The supervisor fills controller-authorized capacity without an AI captain
  turn, using the configured desktop or API sprint-worker route.
- Every worker launch is bound to the controller reservation, attempt token,
  execution unit, and reported branch, worktree, and PR identities.
- Workers return a strict `orka.worker-terminal-result/v1` envelope. Accepted
  outcomes map through `supervisor-lifecycle-v1`; completed outcomes also
  require a fresh authenticated GitHub merge receipt.
- Exact duplicate terminal delivery is a no-op. Stale attempt or execution
  identity is rejected, while malformed or missing output moves only its ticket
  to recovery-ready.
- A terminal transition forces an immediate authoritative replan so newly
  available capacity refills without a polling or model-turn delay.
- Drain now waits for controller-owned active jobs before entering the paused
  state.

## Preserved boundaries

Existing review, security, CI, budget, merge, and controller admission gates
remain authoritative. This release does not add automatic preserved-PR
recovery, resource exclusions, or supervisor takeover after an unclean death.
