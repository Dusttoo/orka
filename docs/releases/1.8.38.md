# Orka 1.8.38

Orka 1.8.38 makes durable-state liveness a runtime-owned contract instead of a
documentation-only expectation.

## What changed

- Adds a bounded, repository-neutral state model covering tickets, attempts,
  execution identity, PR and review state, provider reservations, route and
  sprint breakers, operator decisions, and independent peer work.
- Proves every reachable nonterminal modeled state has a supported exit and
  reports the shortest counterexample trace when one does not.
- Requires operator exits to name a real command and authority, rejects
  undefined or unactionable decisions, and keeps terminal recovery explicit.
- Binds core liveness transitions to the production supervisor's exact job
  events and enumerates cross-domain extensions in the supervisor contract.
- Loads and validates the liveness contract whenever the production supervisor
  loads its lifecycle contract.
- Adds sanitized positive and negative regression fixtures for historical
  tokenless-repair, escalated-review, moved-head, stale-attempt, and
  preserved-PR deadlocks.

## Compatibility

The contract adds startup validation but does not change repository policy,
provider routing, gate requirements, or operator authority. Invalid or stale
runtime contracts fail closed before the supervisor begins dispatching work.
