# Orka 1.6.0

Orka 1.6.0 makes security-review selection a shared, mechanical policy decision
instead of an adapter-specific interpretation of the diff.

## Branch-aware security gates

- Repositories can configure `security_required_source_branches` and
  `security_required_target_branches` with shell-style patterns.
- The new `orchestration-engine.py security-gate` command evaluates those
  patterns from authoritative PR metadata together with the existing
  `security_required_when` diff rules.
- A match on any rule requires the independent security review. This supports
  policies such as every `hotfix/**` branch and every PR targeting `main`, even
  when the changed files contain no configured security keyword.
- Claude and Codex gate procedures use the same decision and stop fail-closed if
  PR metadata, raw diff evidence, configuration validation, or evaluation is
  unavailable.
- Regression coverage includes harmless component-only diffs, source and target
  branch matches, existing diff triggers, malformed configuration, and missing
  diff evidence.

No application-specific branch policy is hard-coded. Each repository opts into
the branch patterns appropriate to its release model.
