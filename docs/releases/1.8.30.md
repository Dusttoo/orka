# Orka 1.8.30

Orka 1.8.30 integrates the disposable phase-worker protocol across Codex
desktop, Claude desktop, and direct API execution routes, completing issue
#113.

## Changed

- Requires every execution adapter to advertise its protocol version and
  supported capabilities before controller reservation or provider work.
- Persists a sanitized compatibility receipt with each accepted phase
  execution.
- Uses one capability builder and fixture contract for Codex desktop, Claude
  desktop, and API routes while preserving each route's required capability.
- Keeps every phase invocation in a fresh model context and passes the same
  bound job, progress, cancellation, malformed-output, and terminal semantics
  through every adapter.
- Rejects mixed protocol versions and missing mandatory capabilities without
  consuming an attempt, provider request, or subscription turn.
- Reports protocol drift as a route-scoped `protocol_incompatibility` instead
  of treating the upstream model provider as unavailable.

## Compatibility

- Existing Orka configuration requires no changes.
- Protocol-compatible Codex, Claude, and API routes continue using their
  existing launch commands and credentials.
- An older or incomplete execution adapter now fails closed before reservation
  and must pass an explicit route repair probe after upgrade.
