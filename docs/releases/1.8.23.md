# Orka 1.8.23

Orka 1.8.23 implements the offline legacy-state migration and deterministic
export slice tracked by issue #117 and accepted in ADR 0001.

## Added

- Inventory and SHA-256 hashing for repository-owned controller, supervisor,
  review-ledger, usage, provider-health, decision, recovery, and external
  receipt state.
- Fail-closed ownership proof for historical parent-level state and exclusive
  migration authority across the supervisor and repository identity.
- A version-2 additive SQLite schema for content-addressed migration receipts,
  source manifests, and normalized legacy records.
- Atomic temporary-database import, integrity checking, deterministic shadow
  comparison, fsync, installation, and exact idempotent replay.
- Canonical, byte-stable JSON export with ordered sections, section/export
  digests, and credential and prompt-body redaction.
- Crash-injection coverage for every import and install boundary.

## Compatibility

- Existing JSON controller and supervisor state remains authoritative.
- Import is explicit and offline; upgrading Orka does not import or activate
  the SQLite store automatically.
- Legacy inputs remain read-only. Production cutover is still owned by issue
  #118.
